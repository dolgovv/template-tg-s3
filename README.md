# Telegram Bot Template

Готовый шаблон для быстрого старта Telegram-бота на TypeScript с простой настройкой под себя.
Работает в [4 режимах](#режимы-работы): от личного облака до CMS для сайта. Режим выбирается только через `.env`, код менять не нужно.

---

## Что внутри

**🎛 Функционал:**

- Навигация по папкам
- Просмотр файлов
- Дерево текущей папки до 5 уровней вложенности
- Добавить/удалить/переименовать папку
- Добавить/удалить/переименовать файл

**🔐 Авторизация администраторов:**

Доступ к боту ограничен списком Telegram ID. Чтобы изменить список админов, которым доступен функционал бота достаточно отредактировать переменную ADMIN_IDS в .env, например: ADMIN_IDS=123456789,987654321

**🌍 Мультиязычность:**

Поддерживаются `ru` и `en` из коробки. Тексты — данные с параметрами (`"Файл {name} удалён"`): параметры экранируются сами, числа склоняются по правилам языка. Изменить текст или добавить язык — несколько строк в `src/app/texts/index.ts`, ядро при этом не правится

**🌐 Прокси из коробки:**

Поддержка HTTP/HTTPS прокси через переменную окружения `PROXY_URL`. Достаточно вписать URL - бот подхватит его при старте.

**📦 S3-хранилище:**
Работает с любым S3-совместимым хранилищем: Garage в том же docker-compose, отдельный сервер или облако (Yandex Object Storage, Selectel, AWS S3 и т.д.). Переключение — только через `.env`.

## Режимы работы

Режим определяется двумя вопросами:

1. **Где лежат файлы?** На вашем сервере (Garage запускается рядом с ботом) или во внешнем S3-хранилище (облако провайдера).
2. **Есть ли сайт, которому нужно знать об изменениях?** Если есть, бот после каждого изменения вызывает хук сайта, и сайт сразу показывает новые файлы.

|                               | Без хука                                         | С хуком `CACHE_INVALIDATE_URL`                      |
| ----------------------------- | ------------------------------------------------ | --------------------------------------------------- |
| **Файлы на вашем сервере**    | 🗂 [Личное облако](#-личное-облако)               | 🌐 [CMS на одном сервере](#-cms-на-одном-сервере)    |
| **Файлы во внешнем S3**       | ☁️ [Безлимитное облако](#️-безразмерное-облако)  | 🚀 [CMS для больших проектов](#-cms-для-больших-проектов) |

### Общее для всех режимов

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен ([подробнее](docs/env-configuration.md#как-получить-токен-бота)).
2. Скопируйте пример настроек: `cp .env.example .env`.
3. Заполните в `.env`:

```env
BOT_TOKEN=1234567890:AAF...       # токен от BotFather
ADMIN_IDS=123456789               # ваш Telegram ID, несколько — через запятую
WEBSITE_NAME=Мои файлы            # название в приветствии
```

Дальше — настройки выбранного режима.

### 🗂 Личное облако

**Файлы на вашем сервере, без хука.**
Своё облачное хранилище в Telegram, как iCloud или Google Drive, только на вашем сервере и без подписки.

- **Подходит для** личных файлов, фото, документов и бэкапов.
- **Ограничение:** места столько, сколько свободно на диске сервера.

**Что сделать:**

1. Добавьте в `.env` (ключи генерируются командами в комментариях):

```env
S3_ENDPOINT=http://garage:3900
S3_REGION=garage
S3_ACCESS_KEY_ID=GK...            # echo "GK$(openssl rand -hex 16)"
S3_SECRET_ACCESS_KEY=...          # openssl rand -hex 32
S3_BUCKET=tg-bot
GARAGE_RPC_SECRET=...             # openssl rand -hex 32
CACHE_INVALIDATE_URL=             # пусто: хук не нужен
```

2. Запустите:

```bash
./start.sh
```

Хранилище и бакет создадутся сами при первом запуске.

### ☁️ Безразмерное облако

**Файлы во внешнем S3, без хука.**
То же личное облако, но место не ограничено диском сервера. Хранилище растёт само, а платите вы только за занятые гигабайты.

- **Подходит для** больших архивов, медиатеки и файлов, которые не помещаются на сервер.
- **Сервер** нужен самый простой: бот почти ничего не хранит сам.

**Что сделать:**

1. В кабинете S3-провайдера (Yandex Object Storage, Selectel, AWS S3 и т.д.) создайте бакет и ключ доступа.
2. Добавьте в `.env`:

```env
S3_ENDPOINT=https://storage.yandexcloud.net   # адрес S3 вашего провайдера, для AWS — пусто
S3_REGION=ru-central1                          # регион бакета
S3_ACCESS_KEY_ID=...                           # ключ из кабинета провайдера
S3_SECRET_ACCESS_KEY=...
S3_BUCKET=my-files                             # бакет, созданный на шаге 1
CACHE_INVALIDATE_URL=                          # пусто: хук не нужен
```

Для AWS и провайдеров без path style добавьте `S3_FORCE_PATH_STYLE=false`.

3. Запустите:

```bash
./start.sh
```

### 🌐 CMS на одном сервере

**Файлы на вашем сервере, с хуком.**
Админка сайта прямо в Telegram: загружаете картинку в бота, и она сразу появляется на сайте. Сайт, бот и файлы живут на одном сервере.

- **Подходит для** лендингов, блогов, портфолио и небольших сайтов.
- **Ограничение:** диск и ресурсы одного сервера.

**Что сделать:**

1. Заполните `.env`, как в режиме [Личное облако](#-личное-облако).
2. Добавьте хук:

```env
CACHE_INVALIDATE_URL=https://example.com/cache/invalidate   # адрес на вашем сайте
CACHE_INVALIDATE_TOKEN=...                                  # openssl rand -hex 32
S3_ROOT_PREFIX=site/                                        # необязательно: бот работает только в этой папке
```

> Укажите **публичный адрес** сайта, а не `localhost`: бот работает в Docker, и для него `localhost` — это сам контейнер бота.

3. На сайте сделайте обработчик, который принимает запрос от бота и сбрасывает кэш. Формат запроса и пример обработчика — в разделе [Сброс кэша сайта](docs/env-configuration.md#сброс-кэша-сайта). Тот же `CACHE_INVALIDATE_TOKEN` пропишите на сервере сайта, чтобы чужие запросы отклонялись.
4. Сайт берёт файлы из Garage по адресу `http://127.0.0.1:3900` с тем же ключом из `.env`.
5. Запустите:

```bash
./start.sh
```

### 🚀 CMS для больших проектов

**Файлы во внешнем S3, с хуком.**
Полноценная CMS: файлы лежат в надёжном облачном хранилище, сайт может отдавать их через CDN, а бот сообщает сайту о каждом изменении.

- **Подходит для** интернет-магазинов, медиа, сайтов с большим количеством картинок и посетителей.
- **Плюсы:** хранилище не ограничено, а сервер бота и сайта можно менять или масштабировать отдельно от файлов.

**Что сделать:**

1. Заполните `.env`, как в режиме [Безразмерное облако](#️-безразмерное-облако).
2. Добавьте хук, как в режиме [CMS на одном сервере](#-cms-на-одном-сервере) (шаги 2–3).
3. Запустите:

```bash
./start.sh
```

### Как сменить режим

- **Включить или выключить хук** — заполнить или очистить `CACHE_INVALIDATE_URL` и перезапустить бота.
- **Переехать с сервера во внешнее S3** — скопировать файлы, например `rclone sync`, поменять настройки S3 в `.env` и снова запустить `./start.sh`.

### Запуск и обновление

`./start.sh` — одна команда для всех режимов:

- проверяет `.env` и подсказывает, чего не хватает, например как сгенерировать ключи Garage;
- сам определяет режим: Garage запускается, только если `S3_ENDPOINT=http://garage:3900`;
- каждый раз **собирает бота из исходников** в Docker, поэтому после любых изменений в коде достаточно запустить его снова. Пересборка быстрая: зависимости берутся из кэша.

Docker нужен для всех режимов. Если у пользователя нет прав на Docker, скрипт сам вызовет его через `sudo`.

Логи бота: `docker compose logs -f bot`.

### Разработка

```bash
./start.sh --dev
```

Бот запускается прямо на вашей машине, без сборки образа, и перезапускается при каждом сохранении файла в `src/`. Если используется Garage, он работает в Docker, как обычно, а бот в Docker на это время останавливается: два бота с одним токеном мешают друг другу.
Нужны Node.js 22+ и pnpm (`corepack enable`). Остановить — `Ctrl+C`, вернуться к обычному запуску — `./start.sh`.

Все переменные `.env` описаны в [Настройке .env](docs/env-configuration.md).

## Структура проекта

```
src/
  core/        ← ядро бота. Не правьте его — так обновления из upstream приходят без конфликтов
    index.ts   ← публичный API ядра: всё, что можно импортировать в app
  app/         ← ваш код
    main.ts    ← точка входа: настройки, свои команды, подключение фич
```

`app/` импортирует только из `core/index.ts`. Всё, что нужно поменять под проект, делается через параметры в `main.ts`:

```ts
const config = configFromEnv(); // всё из .env

const app = createBot({ ...config.bot, defaultLang: "ru" }); // любой параметр можно переопределить

app.bot.command("ping", (ctx) => ctx.reply("pong")); // свои команды — до fileManager

app.use(fileManager({ storage: s3Storage(config.s3), ...config.fileManager }));

await app.start();
```

### Обновление из шаблона

Если проект создан клонированием этого репозитория:

```bash
git remote add upstream <url-шаблона>   # один раз
git fetch upstream && git merge upstream/master
```

Если в `package.json` или `pnpm-lock.yaml` возник конфликт — оставьте зависимости с обеих сторон и выполните `pnpm install`.
